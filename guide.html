PREVIEW 0.1.0 · FIRST SESSION GUIDE

Your local companion,
ready for real work.

This is an early terminal preview for Linux x86_64 and Git projects. The CLI, local runtime and downloaded model are separate. macOS binaries are pending validation.

1. Install the CLI

Download the archive and SHA256SUMS from the release page. Verify and extract the download:

sha256sum --check --ignore-missing SHA256SUMS
tar -xzf devcompanion-0.1.0-linux-x86_64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 755 devcompanion-0.1.0/devcompanion "$HOME/.local/bin/devcompanion"
export PATH="$HOME/.local/bin:$PATH"
devcompanion --version

Add ~/.local/bin to your shell's PATH for future terminals. The archive includes the application license, dependency notices and a quickstart. Checksums verify file integrity; the preview does not have a signed binary release.

2. Prepare a local model

Install Ollama from its official download page. Start ollama serve if the runtime is not already running, then download the starting model:

ollama pull qwen3:4b-instruct-2507-q4_K_M
devcompanion doctor

The initial model has about 2.5 GB of weights. Allow additional space for Ollama, model cache and your project. A supported GPU helps; CPU inference can be slower. This preview was exercised on an i5-12450HX laptop with about 15 GiB usable RAM and an RTX 3050 6 GB GPU. That is an observed setup, not a minimum requirement or a guarantee for other hardware.

Inference quality depends on your model. Set OLLAMA_NO_CLOUD=1 in the runtime environment for local-only Ollama operation. The companion independently restricts its endpoint to loopback and refuses model delegation when declared by the runtime. Use downloaded models and trusted local runtime configuration.

3. Start a continuing session

cd your-git-project
devcompanion init --goal "Finish the login flow"
devcompanion start

Talk about what you are working on. Use /file src/example.py to attach a file and /remember TEXT to save an intention. Startup and relevant project changes can generate a local briefing. Edits settle for 10 seconds; automatic reasoning runs at most once per 90 seconds. Idle observation invokes no model calls.

Capture useful command results from another terminal:

devcompanion run -- npm test
devcompanion explain

A registered action can be proposed, reviewed and explicitly approved:

devcompanion check add tests -- npm test
devcompanion plan "What should I check before finishing?"
devcompanion proposals
devcompanion approve 1

Use the ID displayed for your own proposal. Approval checks the current code fingerprint and exact action definition, and blocks replay. Passing configured checks is evidence for those checks, not a guarantee of complete correctness.

Useful conversation actions

ActionWhat happens
/resumeRefresh your project's current state and remembered intentions.
/contextInspect the observed file sample, context candidates and saved assistant briefings.
/file PATHAttach up to three UTF-8 repository files. They are reread on each question.
/quiet, /assistPause or resume observation and proactive reasoning.
/plan TASKPropose one registered action; nothing runs.
/approve ID, /reject IDDecide whether a proposal executes.
/quitClose the session and end observation.

Local data and privacy

The companion database is ~/.local/share/devcompanion/state.sqlite3 by default, or $XDG_DATA_HOME/devcompanion/. DEVCOMPANION_HOME can relocate it. The directory and database use owner-only filesystem permissions.

  • Stored: user intentions, conversation history, Git fingerprints, bounded command records, assistant briefings and action proposals.
  • Retained per project: the latest 200 messages, 200 command records and 50 assistant briefings. Intentions and proposals remain until removed or the project is forgotten.
  • Command capture keeps the latest 64 KiB from each output stream. Use run --no-save -- COMMAND to avoid saving a sensitive command's record.
  • Source context: bounded manifest/README excerpts, tracked file names and commit subjects. An active companion can read up to two small changed source files. Explicit attachments can include up to three repository text files.
  • No desktop capture, ambient terminal history collection, silent cloud fallback or application usage transmission.

Filename filters avoid common secret/dependency paths in automatic source snippets. Source and command output can still contain confidential information. Keep the runtime trusted and inspect context when needed.

devcompanion privacy
devcompanion memory list
devcompanion memory remove ID
devcompanion forget --yes

forget --yes removes the selected project's local records and reclaims database space without modifying its files. Assistant interpretations remain distinct from saved user intentions and verified command outcomes.

The website serves static files and self-hosted fonts. It has no analytics script. GitHub operates the hosting, downloads and feedback service; its own logging and privacy terms apply. Submitted feedback is public on GitHub. Remove secrets and sensitive command output before posting.

Known limits

Local small models can be wrong. Verify suggestions against your actual code. Memory retrieval uses simple lexical relevance and recency; this preview has no semantic memory graph. Tool proposals are limited to checks you registered. The application does not automatically edit code.

Commands are noninteractive bounded jobs, with no stdin and a default 120-second timeout. Their process group is stopped on timeout, cancellation or completion. Do not use capture for servers or interactive prompts. Your chosen commands may themselves need internet.

Cold model startup can take tens of seconds. The companion requests a 10-minute model keep-alive to reduce reloads; Ollama may still unload it under memory pressure. Model weights, memory use and response quality vary. models --task "TASK" provides local guidance, not benchmark-based routing.

After the initial downloads, core conversation, memory and project awareness run offline. A release smoke test used a network namespace with external connectivity unavailable and successfully generated a local-model answer.

Feedback and support
