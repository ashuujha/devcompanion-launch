PREVIEW 0.3.0 · FIRST SESSION GUIDE

Your local companion,
ready for real work.

A free Linux x86_64 terminal preview for Git projects. The CLI, local Ollama runtime and downloaded models are separate. macOS validation is pending.

1. Install the CLI

Download the archive and SHA256SUMS from the release page, then verify and install:

sha256sum --check --ignore-missing SHA256SUMS
tar -xzf devcompanion-0.3.0-linux-x86_64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 755 devcompanion-0.3.0/devcompanion "$HOME/.local/bin/devcompanion"
export PATH="$HOME/.local/bin:$PATH"
ln -s devcompanion "$HOME/.local/bin/dot"
dot --version

The optional link refuses to replace an existing dot. Skip it if already linked. devcompanion supports the same commands. An already open session uses its previous binary until you quit and reopen it.

2. Set up local inference once

Install Ollama, start its local server and explicitly download a model. Skip the pull if ollama list already shows it.

ollama serve
# In another terminal:
ollama pull qwen3:4b-instruct-2507-q4_K_M

The tested 4B instruct weights take about 2.5 GB. qwen3:1.7b is a smaller tested option around 1.4 GB. Disk size does not prove memory fit or quality. Initial downloads need internet; core operation afterward uses loopback inference. Use a trusted local runtime; declared remote model delegation and cloud names are refused.

3. Make it yours and start

Open a terminal in your actual Git project:

dot companion --name Pixel --pet cat --style mentor
dot prefer "Explain one step at a time"
dot

First use asks before enabling this project. Noninteractive setup uses dot init. At the conversation prompt, describe your actual task. /help shows actions; /home refreshes the dashboard.

Pets: dot, cat, fox, robot or none. Import a small UTF-8 text pet with companion --avatar PATH: up to eight lines, 48 columns and 2048 bytes. These are terminal characters. Response styles are concise, friendly and mentor. Name, style and up to ten global preferences guide the local model; a small model can still miss that guidance.

/model NAME verifies a downloaded brain, switches the current conversation and saves it. --model NAME is a temporary override. There are no automatic downloads. Running tasks keep their selected model.

The visible session observes this Git project and explicitly recorded commands. Edits settle for ten seconds; proactive reasoning defaults to at most once per 90 seconds. Idle observation makes no model calls. /quiet saves a quieter default; /assist resumes it. /quit leaves.

4. Delegate, review, check and revise

Use /work followed by a development goal. A local worker investigates bounded repository text and returns a patch or report. /tasks lists work; /activity ID shows actual activity; /review ID shows the report and diff.

dot check add tests -- npm test
dot task review ID
dot task apply ID
dot task verify ID tests
# After a completed failed task check:
dot task revise ID

Use IDs shown for your own tasks. Choose the actual check for your project. Each correction is a separate task requiring review and explicit application. task verify ID tests --revise can prepare it after a failure, but still exits unsuccessfully for the failed check. Chat equivalents: /apply ID, /task-check ID CHECK and /revise ID.

task show ID reports current verification separately from historical status. Changed code or check definitions invalidate passing evidence. task rollback ID restores exact task content only on unchanged applied code and refuses later edits. Roll back child tasks before their parent.

Work can continue after chat closes while the laptop stays on. Returning with start resumes dead queued/running workers using fresh evidence. A dead apply/check/rollback operation needs task recover ID, which marks its result unknown and executes nothing. Inspect files and any surviving check processes before retrying. Old applied tasks from pre-0.3 releases lack the post-application state required by task verification/rollback; ordinary verify CHECK still works.

Bounds: three active tasks, serialized task inference, eight model turns, up to three small UTF-8 files including new files. Existing files must be at most 32 KiB; individual inserted text is bounded. Supported ordinary paths are required; symlinks, ignored new paths and common secret/dependency paths are excluded. Filename filters cannot recognize every secret. New files cannot overwrite existing files. No model-generated commands run.

5. Memory you control

dot memory add "Use SQLite for local storage"
dot memory list
dot memory edit ID "Use SQLite with explicit migrations"
dot memory search SQLite
dot memory learn
dot memory review
dot memory accept ID
dot memory reject OTHER_ID

Goals and decisions stay in this project. Learning proposes guidance from the latest twelve saved user messages, with copies of its cited sources. Proposals remain inactive until accepted. Preferences become global; decisions stay in this project. companion --learning on enables proposals after conversation, at most once every five minutes; the default is off. No model training occurs. In chat: /decision TEXT, /learn, /memory-review, /memory-accept ID, /memory-reject ID.

Keyword search needs no model. Optional semantic retrieval needs a local embedding model downloaded explicitly:

ollama pull all-minilm:22m
dot memory index --embedding-model all-minilm:22m
dot memory search "database persistence choice"
dot memory index --clear

The embedding weights take about 45 MB. Indexing covers the latest 200 notes, using a 350-byte prefix per note. It runs locally on CPU. Edits invalidate vectors; repeat indexing after changes. Unavailable embeddings fall back to keyword retrieval. This is bounded retrieval, with no semantic memory graph. Embeddings can cause a chat model reload on small machines.

6. Choose budgets and compare models

dot doctor
dot resources --device cpu --context 4096 --reply-tokens 256 --keep-alive-seconds 0
dot benchmark --category explain --models qwen3:1.7b qwen3:4b-instruct-2507-q4_K_M --task "Explain our storage choice"
dot benchmarks
dot rate ID useful
dot rate OTHER_ID unhelpful
dot route --category explain

Inspect each actual response before rating. Comparisons record total time, time to first text and actual prompt/output counts when Ollama provides them. Routing suggests the fastest latest response rated useful for the latest identical task, current code/context/settings and unchanged model digest. Add --apply to save the suggestion. It does not infer quality for other tasks or switch automatically. Loading, order and caches affect timings; these are local observations, not standardized benchmarks.

CPU/auto, context, reply/task token caps, model retention and proactive cooldown are explicit controls. Lower limits can reduce context coverage and answer quality. The default requests ten-minute model retention; Ollama may unload under pressure. models --task TEXT gives model-generated advice; measured route has a separate evidence requirement.

7. Optional shell and editor adapters

dot integration bash prints a function to save and source explicitly. Then d cargo test records that chosen command. It does not capture existing commands or shell history. dot integration vscode prints process tasks for registered checks: merge them into your own .vscode/tasks.json. It does not modify editor settings or watch unsaved buffers. Keep a companion session open in another terminal for awareness.

Local data and private copies

The default database is ~/.local/share/devcompanion/state.sqlite3, or $XDG_DATA_HOME/devcompanion/. DEVCOMPANION_HOME relocates it. Storage and output copies use owner-only permissions.

  • Stored per project: goals/decisions, latest 200 messages, 200 bounded command records, 50 briefings, 200 model measurements, proposals, optional vectors, learned suggestions with user evidence, tasks/activity/reports and original/proposed file text.
  • Identity, pet, style, model, proactive/learning defaults, resource budgets and global preferences share the local database. forget retains global settings and preferences; unprefer ID removes a preference.
  • Command capture retains the latest 64 KiB per output stream. run --no-save -- COMMAND avoids saving that command's record. Conversation, source and command output can contain sensitive information.
  • Context includes bounded source/manifests, tracked file names and commit subjects. Awareness can read two small changed files; explicit attachments can cover three repository files.
  • No desktop capture, ambient terminal history capture, silent cloud fallback or application usage transmission.
dot privacy
dot data export /private/path/project.json
dot data export /private/path/project-with-guidance.json --include-personalization
dot data backup /private/path/all-projects.sqlite3
dot forget --yes

Exports contain only the selected project's records, with global identity/preferences only if requested. Backups consistently copy the entire database, including every project's private content. Model weights are excluded. Outputs refuse overwrites. Keep them private. Forgetting a project leaves earlier exported copies intact and does not change project files; stop active work first.

To inspect a backup safely, use a separate data directory with a copy named state.sqlite3 and point DEVCOMPANION_HOME there. Do not replace a live database while tasks run.

This site has no analytics script and uses self-hosted fonts. GitHub hosts downloads and public feedback; its own logging and terms apply. Remove private content before submitting feedback.

Evidence and remaining limits

The static binary passed 52 integration tests, real terminal checks and a continuing session without external connectivity. The real 4B model proposed a project decision from a user statement; optional local embeddings retrieved it. Actual CPU response counters were captured for two models. See the recorded workflow and release notes for task evidence.

Small models can produce wrong or poorly worded answers even when a patch is valid. Review actual changes and relevant checks. Larger edits, broader local tools, a full editor extension, a graphical pet and general autonomous completion remain future work. This is an early preview; user retention and broad coding quality are not established.

Recorded commands are noninteractive jobs with no stdin and a default 120-second timeout; process groups stop on timeout, cancellation or completion. Use them for checks rather than servers or interactive prompts. Your own chosen commands can require internet.
